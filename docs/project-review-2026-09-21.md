# 프로젝트 분석과 개선 기록

기준 커밋: `1876090` · 작업일: 2026-09-21

이 프로젝트는 20개 분석 화면을 가진 React 대시보드와 Express API, AWS 수집·보관 계층으로 구성되어 있습니다. 서버의 조직 구분, 비용 집계, 캐시, 응답 변환에는 기존 회귀 검사가 있었지만, 브라우저의 조회 전환과 입력·키보드 동작을 확인하는 테스트는 없었습니다. 실제 화면 동작을 재현해 공통 조회 처리와 사용자 편의 기능을 보강했습니다.

## 확인한 문제와 반영한 변경

| 영역 | 확인한 문제 | 반영한 변경 |
|---|---|---|
| 조회 안정성 | 화면을 바꿔도 이전 요청이 계속 실행됨. 잘못된 성공 응답을 빈 객체로 취급하고, `refetch()`가 요청 완료 전에 반환됨 | AbortController, 응답 형식 검사, 65초 제한, 실제 완료를 기다리는 재조회, 이전 조직·기간에서 보관한 콜백 차단 |
| 조직·시점 구분 | Cost Live의 마지막 성공값이 조직 전환 후에도 남고, 과거 날짜 선택 중 이전 스냅샷 시간이 표시될 수 있음 | 조직별 last-good 구분, 날짜에 맞는 시간 목록만 표시, 오류·과거 조회에서 데이터가 섞이지 않도록 보호 |
| 날짜 선택 | 존재하지 않는 날짜·빈 값·역전 구간이 적용될 수 있고, UTC 서쪽 시간대에서 날짜가 하루 앞당겨 표시됨 | ISO 달력 날짜와 기간 검증, 잘못된 URL의 안전한 기본값, UTC 표시, 입력 오류 안내, 취소·Escape·포커스 복귀 |
| 화면 탐색 | 많은 메뉴를 직접 훑어야 하며 화면 전환 후 이전 스크롤 위치가 남음 | 메뉴 검색, Ctrl/⌘+K, Enter 이동, 페이지별 제목과 스크롤·포커스 갱신 |
| 표 활용 | 실시간 비용의 구성원 검색과 표 내보내기가 없고, 정렬 헤더가 마우스 클릭만 지원 | Users·Cost Live 검색·초기화·결과 수·CSV, 현재 검색·정렬 순서 유지, 버튼 기반 정렬과 `aria-sort` |
| 모바일·키보드 | 메뉴와 사용자 상세를 열 때 포커스 관리가 부족하고, 감사 필터와 긴 Markdown 문자열이 화면 밖으로 넘침 | 메뉴 포커스 제한·복귀, 상세 열기·닫기, 반응형 필터 배치, 긴 문장·경로 줄바꿈 |
| AI 채팅 | 한국어 조합 확정 Enter가 전송으로 처리됨. 종료한 스트림의 응답이 뒤늦게 상태를 변경할 수 있음 | IME 조합 검사, 중지·초기화·이동 시 취소, 요청 소유권 확인, 중단된 응답 안내 |
| 오류 복구 | 조회 오류에 재시도 버튼이 없고, 페이지 렌더링 오류가 앱 전체에 영향을 줄 수 있음 | 한·영 재시도 버튼, 페이지 오류 경계, 메뉴를 통한 이동과 새로고침 |
| 시작·문서 | 브라우저 저장소 접근 제한 시 시작 실패 가능. 변경 내역 언어 구분 정규식이 동작하지 않음 | 선택적 설정 저장, 언어별 변경 내역 표시 |
| 로딩·의존성 | 모든 화면이 하나의 JavaScript 파일에 포함됨. 의존성 보안 공지 확인 | 화면·채팅 패널 지연 로딩, Vite·라우터·업로드·쿼리 파서 보안 패치 |

## 사용할 수 있는 편의 기능

- **메뉴 찾기:** Ctrl+K 또는 ⌘K → 페이지 이름 입력 → Enter. 현재 조직·그룹을 유지하며, 날짜는 기존 화면별 기본 정책을 따릅니다.
- **표 저장:** Users 또는 Cost Live에서 검색·정렬 → CSV 다운로드. 그룹 필터와 휴면 사용자 필터도 해당 화면의 표시 결과에 반영됩니다.
- **조회 복구:** 오류 안내에서 다시 시도. 렌더링이나 화면 파일 로딩에 실패한 경우 메뉴 이동 또는 새로고침을 사용할 수 있습니다.
- **키보드 조작:** 정렬 버튼은 Enter/Space로 작동합니다. 날짜 선택기와 모바일 메뉴는 Escape로 닫을 수 있습니다.

CSV는 화면의 `maskEmail()` 판정을 따르며, 숫자를 표시용으로 축약하지 않고 저장합니다. 쉼표·따옴표·줄바꿈을 처리하고 UTF-8 BOM을 포함합니다. 문자열이 스프레드시트 수식으로 실행되지 않도록 이스케이프합니다. Cost Live의 KPI는 선택한 그룹 전체를 나타내고, 표 하단 합계와 CSV는 검색 결과를 따릅니다.

## 검증 방법

```bash
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit
```

- `tests/run-all.sh`: 기존 서버·수집기·보안 훅·구조 회귀 검사.
- `tests/frontend/`: 실제 React 컴포넌트와 훅을 이용한 날짜, 조직 전환, 지연 콜백, 요청 취소, 채팅, 검색·정렬·내보내기 검사.
- `tests/e2e/`: 프로덕션 빌드를 Chromium의 데스크톱·모바일 화면에서 실행. 20개 페이지, 날짜, 재시도, 단축키, CSV 다운로드, IME, 한국어 표시를 확인.

브라우저 검사는 저장소의 샘플 생성기와 합성 API 응답을 사용합니다. 이 결과는 프런트엔드 동작과 기존 서버 회귀 검사의 근거이며, 운영 API 응답이나 AWS 배포 상태를 검증한 결과는 아닙니다.

## 의존성 관리

React 18·Node 20 호환을 유지하면서 Vite 6, React Router 7의 선언형 라우팅, Vitest 4를 사용합니다. Express 4가 끌어오는 이전 `qs` 버전은 `^6.16.0`으로 재정의했습니다. Express를 갱신할 때 이 재정의의 필요성을 함께 검토해야 합니다. 보안 점검은 루트 `package-lock.json`을 대상으로 합니다.
